Capítulo 02

Criar o primeiro servidor

1. Objetivo e explicação

Um servidor é um programa que espera pedidos. O navegador envia uma requisição HTTP; nossa função escreve uma resposta. Começaremos com texto e refinaremos as rotas depois.

Relembrando Go desde o início
  • go.mod identifica o módulo, que reúne os arquivos do projeto. go mod init cria esse arquivo.
  • main.go contém o código; package main indica um programa executável, e func main() é seu ponto de entrada.
  • import disponibiliza ferramentas de outros pacotes. Usaremos apenas a biblioteca padrão.
  • func declara uma função. Na função handler, r é o pedido recebido e w é onde escrevemos a resposta.
  • go build compila o código. Ele será executado dentro da imagem no próximo capítulo.

2. Pseudocódigo

Pseudocódigo · não executar
DEFINIR uma função para responder
QUANDO chegar um pedido:
    INFORMAR que a resposta é texto UTF-8
    ESCREVER a mensagem
INICIAR servidor na porta 8080

3. Sua tentativa

Comece pelo terminal: siga os comandos abaixo para criar os arquivos. A versão mínima no módulo será go 1.26.0; o compilador utilizado é Go 1.27.2. São informações diferentes: a versão mínima permite que compiladores compatíveis mais novos construam o projeto.

Terminal · criar os arquivos no macOS/Linux

docker run --rm --user "$(id -u):$(id -g)" -e GOCACHE=/tmp/go-cache -v "$PWD:/app" -w /app golang:1.27.2-bookworm sh -c 'go mod init grupo-estudo/minha-pratica && go mod edit -go=1.26.0'

# Conferir os arquivos e o módulo criado.

pwd mostra a pasta atual; ls lista arquivos; touch cria um arquivo vazio; cat mostra seu conteúdo. No comando Docker, -v liga a pasta atual à pasta /app do container, permitindo gravar go.mod no computador; -w escolhe a pasta de trabalho. --user mantém a propriedade dos arquivos no seu usuário, e GOCACHE usa uma pasta temporária para o cache.

Se go.mod já existir, não rode go mod init novamente: confira seu conteúdo. No Windows, crie os arquivos pelo editor e copie o go.mod completo abaixo; os comandos acima usam sintaxe de macOS/Linux. Se Go estiver instalado localmente, a alternativa é go mod init grupo-estudo/minha-pratica seguido de go mod edit -go=1.26.0.

package main

import (
    "fmt"      // Escreve a mensagem na resposta HTTP.
    "log"      // Registra a inicialização ou um erro do servidor.
    "net/http" // Ferramentas HTTP da biblioteca padrão.
    "time"     // Unidade de tempo para o limite de leitura.
)

// w recebe a resposta; r contém o pedido feito pelo cliente.
func handler(w http.ResponseWriter, r *http.Request) {
    // A primeira versão responde em qualquer caminho; refinaremos depois.
    w.Header().Set("Content-Type", "text/plain; charset=utf-8")
    fmt.Fprintln(w, "Olá, grupo de estudo!")
}

func main() {
    server := &http.Server{
        Addr: ":8080", // Escuta em todas as interfaces, na porta 8080.
        Handler: http.HandlerFunc(handler), // Usa nossa função para responder.
        ReadHeaderTimeout: 5 * time.Second, // Limita a espera pelos cabeçalhos.
    }
    log.Println("Servidor ouvindo em :8080")
    log.Fatal(server.ListenAndServe()) // Mantém o servidor esperando pedidos.
}

package main define um programa executável. Os imports trazem ferramentas da biblioteca padrão. handler recebe r (pedido) e w (resposta). main inicia o servidor. ListenAndServe fica esperando pedidos. Nesta primeira versão qualquer caminho recebe a mensagem, inclusive /health; isso muda no capítulo 4.

Arquivo main.go · solução completa; substitui o arquivo inteiro
package main

import (
    "encoding/json" // Converte valores Go para JSON.
    "fmt"           // Escreve texto na resposta.
    "log"           // Registra eventos no terminal.
    "net/http"      // Servidor, requisições e códigos de status HTTP.
    "time"          // Duração do limite de leitura.
)

func handler(w http.ResponseWriter, r *http.Request) {
    log.Printf("%s %s", r.Method, r.URL.Path) // Ex.: GET /health.

    // Só existem estas duas rotas. O return encerra esta resposta.
    if r.URL.Path != "/" && r.URL.Path != "/health" {
        http.NotFound(w, r)
        return
    }
    // As rotas conhecidas aceitam apenas GET.
    if r.Method != http.MethodGet {
        w.Header().Set("Allow", "GET") // Informa o método permitido.
        http.Error(w, "Use GET", http.StatusMethodNotAllowed)
        return
    }
    if r.URL.Path == "/health" {
        w.Header().Set("Content-Type", "application/json; charset=utf-8")
        // Um mapa associa a chave status ao valor ok.
        json.NewEncoder(w).Encode(map[string]string{"status": "ok"})
        return // Não acrescente a mensagem de texto ao JSON.
    }
    w.Header().Set("Content-Type", "text/plain; charset=utf-8")
    fmt.Fprintln(w, "Olá, grupo de estudo!") // Sem erro: status padrão 200.
}

func main() {
    server := &http.Server{
        Addr: ":8080",
        Handler: http.HandlerFunc(handler),
        ReadHeaderTimeout: 5 * time.Second,
    }
    log.Println("Servidor ouvindo em :8080")
    log.Fatal(server.ListenAndServe())
}

Por que funciona?

Cada return encerra a função para evitar juntar respostas diferentes. Content-Type diz ao cliente o formato do corpo. A ordem das verificações faz caminhos desconhecidos retornarem 404, mesmo se o método for diferente de GET; rotas conhecidas retornam 405 para outros métodos. Os arquivos go.mod, Dockerfile e .dockerignore continuam como no capítulo 3.

package main

import (
    "encoding/json" // Converte valores Go para JSON.
    "fmt"           // Escreve texto na resposta.
    "log"           // Registra eventos no terminal.
    "net/http"      // Servidor, requisições e códigos de status HTTP.
    "time"          // Duração do limite de leitura.
)

func handler(w http.ResponseWriter, r *http.Request) {
    log.Printf("%s %s", r.Method, r.URL.Path) // Ex.: GET /health.

    // Só existem estas três rotas. O return encerra esta resposta.
    if r.URL.Path != "/" && r.URL.Path != "/health" && r.URL.Path != "/tarefas" {
        http.NotFound(w, r)
        return
    }
    // As rotas conhecidas aceitam apenas GET.
    if r.Method != http.MethodGet {
        w.Header().Set("Allow", "GET") // Informa o método permitido.
        http.Error(w, "Use GET", http.StatusMethodNotAllowed)
        return
    }
    if r.URL.Path == "/tarefas" {
        w.Header().Set("Content-Type", "application/json; charset=utf-8")
        // Lista fixa em memória; não existe banco ou persistência nesta etapa.
        tarefas := []string{"Entender imagens", "Executar containers"}
        json.NewEncoder(w).Encode(tarefas)
        return
    }
    if r.URL.Path == "/health" {
        w.Header().Set("Content-Type", "application/json; charset=utf-8")
        // Um mapa associa a chave status ao valor ok.
        json.NewEncoder(w).Encode(map[string]string{"status": "ok"})
        return // Não acrescente a mensagem de texto ao JSON.
    }
    w.Header().Set("Content-Type", "text/plain; charset=utf-8")
    fmt.Fprintln(w, "Olá, Docker!") // Sem erro: status padrão 200.
}

func main() {
    server := &http.Server{
        Addr: ":8080",
        Handler: http.HandlerFunc(handler),
        ReadHeaderTimeout: 5 * time.Second,
    }
    log.Println("Servidor ouvindo em :8080")
    log.Fatal(server.ListenAndServe())
}

Por que funciona?

A lista é um []string, uma sequência de textos. O encoder produz um array JSON. Os dados são fixos no código; não há cadastro nem persistência. Próximos estudos: configuração por ambiente, PostgreSQL como serviço, volumes, prontidão do banco, múltiplas etapas e execução sem root.
