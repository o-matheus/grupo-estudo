04 · Antes do Docker7:00–8:00

O que é um servidor?

Um servidor é um programa que recebe pedidos de clientes, trata esses pedidos e envia respostas.

NavegadorCliente: faz o pedido e recebe a resposta
Pedido HTTP→
←Resposta: texto, JSON ou status de erro
Servidor GoRecebe e trata o pedido; envia a resposta

Neste exemplo, o programa Go é o servidor. Ele recebe pedidos na porta 8080.

Notas · 7:00–8:00

Comece pela definição: servidor é o programa que recebe pedidos dos clientes, trata-os e envia respostas. Identifique o navegador como cliente e o programa Go como servidor. Mostre a seta do pedido indo para o servidor e a seta da resposta voltando ao navegador. A porta 8080 é onde nosso programa recebe os pedidos. Deixe a publicação de portas e as interfaces do container para o slide de execução com Docker.

06 · A receita10:00–13:00

Seis linhas para a primeira imagem.

FROM golang:1.27.2-bookworm
WORKDIR /app
COPY go.mod main.go ./
RUN go build -o /app/servidor .
EXPOSE 8080
CMD ["/app/servidor"]

FROM · imagem com o compilador Go

WORKDIR · pasta dentro da imagem

COPY · arquivos do projeto

RUN · compilar durante a construção

EXPOSE · documentar a porta

CMD · iniciar o servidor no container

EXPOSE não publica a porta. RUN acontece no build; CMD, na execução.

Notas · 10:00–13:00

Leia cada linha. A imagem oficial contém o Go; não precisamos instalar Go no computador. O primeiro exemplo mantém compilador e servidor na mesma imagem. Pergunte quando RUN e CMD são executados.

10 · Compose22:00–26:00

A execução também vira um arquivo.

compose.yaml

services:
  app:
    build: .
    ports:
      - "${HOST_PORT:-8080}:8080"

HOST_PORT permite usar outra porta; o padrão é 8080.

Libere a porta e inicie

docker stop estudo
docker rm estudo
docker compose up --build

Em outro terminal

docker compose ps
docker compose logs app
docker compose down

Dockerfile define a construção. Compose registra como iniciar os serviços.

Notas · 22:00–26:00

Execute na mesma pasta do compose.yaml. Pare o container anterior para evitar disputa pela porta. app é o nome do serviço, não o nome gerado do container. Compose pode reunir API e banco; hoje usamos um serviço. down remove os containers e a rede do projeto, mantendo a imagem.
